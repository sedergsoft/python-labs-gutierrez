## Оценка сложности основных алгоритмов

| Операция | Функция | Сложность | Обоснование |
|---|---|---|---|
| Чтение CSV | `read_orders` | **O(n)** | один проход по n строкам |
| Фильтрация | `filter_by_status` | **O(n)** | list comprehension, n сравнений |
| Сортировка | `sort_orders` | **O(n log n)** | Timsort внутри `sorted()` |
| Сохранение | `save_orders` | **O(n)** | одна запись на заказ |
| Группировка | `group_by_customer` | **O(n log n)** | O(n) группировка + O(k log k) сортировка (k ≤ n) |
| Удаление cancelled | `remove_cancelled` | **O(n)** | один проход, новый список |
| Максимум (рек.) | `max_order_recursive` | **O(n)** | T(n) = T(n-1) + O(1) |
| Максимум (итер.) | `max_order_iterative` | **O(n)**, память **O(1)** | один цикл |
| Линейный поиск | `linear_search` | **O(n)** | перебор всех элементов |
| Бинарный поиск | `binary_search` | **O(log n)** | отбрасывание половины на каждом шаге |
| Полный отчёт | `generate_report` | **O(n log n)** | доминирует сортировка групп |

Эксперимент (задача 16): 500 000 заказов обрабатываются за десятки
миллисекунд; удвоение n удваивает время → подтверждение O(n).

Эксперимент (задача 19): 1 000 000 ID, 1000 поисков —
линейный 160 с, бинарный 0,0066 с (~24 400× быстрее),
что согласуется с `n / log₂ n ≈ 50 000` по порядку величины.
